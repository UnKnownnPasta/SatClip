# AWQ: Activation-aware Weight Quantization for LLM Compression and Acceleration

## Problem
Large language and vision-language models are too big for edge devices in 16-bit precision. Naive 4-bit rounding hurts accuracy, while methods that reconstruct weights with backpropagation or second-order updates can overfit the small calibration set and transfer poorly to other domains.

## Approach
AWQ observes that a small fraction of weight channels matter most, and that importance is better judged from activation magnitudes than from the weights themselves. Instead of keeping those channels in higher precision (which is awkward for hardware), it scales salient channels up before quantization (and compensates in the inputs), choosing scales from activation statistics. No backpropagation or reconstruction is needed, so little calibration data is required and the method generalises across domains and modalities. The authors also release TinyChat, an inference framework for 4-bit models on edge GPUs.

## Data and benchmarks
Language modelling and instruction-following benchmarks across LLaMA and Llama-2 family models and others, plus multimodal models; on-device speed tests on desktop and mobile GPUs.

## Key results
Per the abstract: protecting about 1% of salient weights greatly reduces quantization error; AWQ beats prior methods on language and domain-specific benchmarks and on multimodal models; TinyChat runs more than 3 times faster than the Hugging Face FP16 implementation on desktop and mobile GPUs and can run the 70B Llama-2 on mobile GPUs.

## Limitations
- Speed results are for GPUs (desktop, mobile, Jetson class); CPU speedups depend on the runtime, which the paper does not focus on.
- Weight-only quantization; activations stay in 16-bit, so memory bandwidth, not compute, is what improves.
- Calibration data still matters somewhat; very different input domains (satellite image tokens) were not tested.
- Alternative GPTQ (Frantar et al., ICLR 2023) is the main competitor; we did not compare them ourselves.

## What it means for SatClip
- After merging LoRA adapters (entries 059, 060), quantize the VLM's language model to 4-bit for distribution; AWQ is supported in common runtimes, and GGUF via llama.cpp is the simpler path for pure CPU.
- Use a calibration set drawn from real SatClip prompts (district names, dates, flood and crop questions), not generic web text.
- Re-run the full evaluation after quantization: parse accuracy of instrument calls and abstention rate must not drop; only the explanation text may vary.
- Quantization never touches the instruments, so reported numbers stay identical whatever precision the VLM uses; say this explicitly in the documentation.
